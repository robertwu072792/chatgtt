# Devlog - 2026-08-11

## Reference-detail overlook pass without the overhead wall

The user correctly described the accepted V10 overlook as visually simple compared with the supplied industrial reference, and asked for the same treatment except for its upper separating wall. The pass retains V10's tested stair and deck footprint while rebuilding its presentation from a greybox into a layered low-poly facility.

Blender MCP backed up the accepted source to `/tmp/concourse_v2_before_reference_detail_pass.blend`. Both mirrored overlooks now have segmented ballistic-glass bases, caps, clamps and post lights; recessed lower panels inside the open outer rail; layered inner and outer deck fascia with narrow light channels; flush floor plate joints, route dashes and portal threshold grating; and two grounded tapered gate pylons with footings, inset dark panels and vertical lime blades. The former horizontal gate header was removed rather than restyled, leaving the top open as requested. The equipment box remains freestanding and the straight objective-facing glass line is unchanged.

All additions stay inside the existing ten merged material roles and use analytic geometry only. No texture, imported mesh, new material role, light object, shadow caster, camera, shader pass or runtime callback was added. The shell moves from 24,568 to 30,680 triangles. The final compressed Blender source is 437,219 bytes and the shipping GLB is 2,113,776 bytes.

The first compressed save could not be reopened by Godot's background Blender importer because edit-time orphan datablocks survived the merge operators. The live scene meshes themselves validated cleanly; purging 140 orphaned datablocks and resaving fixed the source. A separate Blender 5.1.1 background process then reopened the compressed file successfully and reported all ten scene objects.

The old `OverlookGateHeader` still existed in the Godot gameplay contract after the visual header was deleted. Although it sat above player height, it would have let shots hit invisible geometry. Concourse layout V11 removes that record for both teams, changing the contract from 134 to 132 solids and advancing the network protocol from 21 to 22 so older collision layouts cannot silently pair with the new build. The map exercise now rejects any surviving gate header.

Godot MCP reimported the Blender source and shipping GLB, supplied both editor and live-game visual evidence, and completed a clean start/stop cycle. All 19 exercise scripts pass, including continuous floor-to-overlook traversal and authored coverage for all 132 gameplay solids. The live desktop preview reports 120 FPS, 11 draw calls, 30,792 primitives and 0.008682 seconds process time. This is desktop evidence only; no iPhone or iPad was launched or deployed, and no mobile GPU, thermal, battery or touch-feel claim is made.

## Single-stair asymmetric overlook rebuild

The user rejected V11's remaining straight, two-stair bridge layout and supplied a precise movement contract. The new second floor must begin narrow, widen into a combat platform and narrow again; use only a front-left main stair; place one full-height angled blast wall at its landing; leave a glass-free jump opening to normal floor-one terrain; use glass only on the nuclear-objective-facing edge; and offset one chest-high equipment box toward that glass. The user also explicitly prohibited a second stair, a symmetric bridge, repeated upright panels, a roof, a lower ramp, suspended pieces, or edits to floor one, the outer wall and the right-side buildings.

Blender MCP first preserved the rejected V11 source at `/tmp/concourse_v2_before_one_stair_platform_redesign.blend`, restored the clean V10 source from `/tmp/concourse_v2_before_reference_detail_pass.blend`, and removed only disconnected geometry islands inside the two old overlook bounds. The two rebuilt overlooks are exact 180-degree rotations. Each uses one watertight stepped deck, ten broad stair treads, closed trapezoid stair side walls, thick metal handrails and a flush top landing. A layered 25-degree blast wall remains more than 0.5 m inside the platform. Its inner-left side opens directly over the untouched concourse floor. The inner glass starts after that opening and uses a continuous metal base, framed panes and a top cap; the outer edge uses solid industrial parapets rather than duplicated glass. The equipment cover sits toward the glass with a broad outer route around it.

The source remains ten merged analytic material-role meshes with no texture, imported mesh, new material role, light, camera, shadow caster, runtime node or frame callback. `RiftlineMapLayout.VERSION` advances to 12 and the collision contract returns to 134 solids. `RiftlineNetwork.PROTOCOL_VERSION` advances to 23 so the one-stair layout cannot pair with older clients. The map exercise now requires the exact V12 pieces, rejects every legacy ramp/gate/straight-floor record, checks every rotated blast-wall corner for 0.5 m clearance, climbs the one stair, traverses around the angled wall and offset box, and verifies the jump opening lands on a flat floor normal. The visual exercise freezes the new 49,592-triangle shell and confirms authored geometry covers every gameplay solid.

Godot MCP reimported both assets and live-previewed the result. Independent headless import is clean, all 19 exercises pass without script errors, and a separate Blender background process reopens the compressed source with ten mesh objects. The desktop preview reports 120 FPS, 11 draw calls, 49,704 primitives and 0.008818 seconds process time. The final local source is 623,315 bytes and the GLB is 3,370,884 bytes. Per the user's instruction this candidate is not committed or pushed; Blender approval is still required. No phone or tablet was launched or deployed.
